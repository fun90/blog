过去三个月把日常开发切到终端 Agent 后，我最终收敛出一套非常轻量的主力组合：**Pi + Magpie**。

核心原则只有一条：**Pi 保持极简，只靠少数精选扩展撑起终端编码；Magpie 负责背后的多模型调度与高频协作能力**。

## 一、Pi：极简内核 + 3 个月精选扩展

Pi（`pi-coding-agent`）本身只保留读、写、改、执行命令等核心能力，其余全部交给 TypeScript 扩展。装了又删三个月后，真正每天都在用的只剩下面这几项：

| 分类 | 扩展 | 解决的痛点 | 定位 |
| :--- | :--- | :--- | :--- |
| 交互体验 | `pi-cc-extensions` | 紧凑 TUI、分栏 diff、长输出折叠 | **终端必装** · ACP 免装 |
| 交互体验 | `@juicesharp/rpiv-ask-user-question` | 歧义时弹窗选选项，减少瞎猜返工 | **必装** · 防跑偏 |
| 交互体验 | `@pi-archimedes/session-name` | 自动命名会话，方便回溯历史记录 | **推荐** · 省心 |
| 检索联动 | `@ff-labs/pi-fff` | FFF 极速模糊搜文件与内容 | **必装** · 提速 |
| 检索联动 | `pi-agent-browser-native` | 原生浏览器自动化，改完页面直接自检 | **按需** · 前端利器 |
| 检索联动 | `pi-mcp-adapter` | 替代内置 MCP，按需挂载外部工具 | **推荐** · 生态入口 |
| 协作控本 | `@maxiaochao/pi-background-tasks` | 长命令丢到后台跑，结束后自动通知 Agent | **推荐** · 不干等 |
| 协作控本 | `pi-advisor-flow` | 快模型日常执行，强模型关键节点把关 | **核心** · 省钱稳 |
| 协作控本 | `pi-agents` | 命名子代理并行，隔离搜索噪音 | **进阶** · 拆任务 |
| 省 Token | `on-demand-tools`（本地扩展） | 重型工具按需加载 | **进阶** · 控上下文 |
| 省 Token | `rtk`（由 Magpie 安装） | 精简 Shell 命令输出 | **进阶** · 控上下文 |

  1. <strong>双模型分层</strong>：用 `pi-advisor-flow` 把日常体力活交给快模型，只在「定方案」「卡壳 3 轮」「最终验收」请出强模型，成本直降且成功率更高。<br />

### session-name：触发时机与省钱配置

它在 Agent 一轮运行结束时（`agent_end`）后台生成标题，不阻塞界面。

| 情况 | 行为 |
| :--- | :--- |
| 会话还没有名字 | 取首条用户消息和首条带文字的回复，各截前 500 字符，生成 3–8 个词的标题 |
| 已用 `--name` 或 `/name` 命名 | 跳过，手动命名优先 |
| 临时会话（没有会话文件） | 跳过 |
| 生成失败 | 之后的轮次重试，累计 3 次后停止 |

不配置时，标题请求走**当前对话模型**。在 `~/.pi/agent/settings.json` 里合并下面这项，改用可用模型中单价最低的一个，我这里是 Haiku：

```json
{
  "archimedes.sessionName": {
    "model": "magpie/claude/claude-haiku-5-5"
  }
}
```

<Callout type="warning" title="模型名写错会静默回退">
  找不到 <code>model</code> 指定的模型时，扩展会改用当前模型且不提示。先用 <code>pi --list-models haiku</code> 核对名称，写成 <code>provider/id</code> 的完整形式。
</Callout>

换便宜模型主要省的是费用，单次输入 token 量基本不变（内容本来就有截断）。这次调用也不计入底部状态栏的用量统计。

### on-demand-tools：下载本地扩展

它让浏览器、子代理、MCP 三组工具默认收起，模型需要时调用 `load_tools` 启用。

**附件下载**：<a href="/downloads/on-demand-tools.ts" download>on-demand-tools.ts</a>

放到 `~/.pi/agent/extensions/` 目录后重启 Pi。三组分别对应 `pi-agent-browser-native`、`pi-agents`、`pi-mcp-adapter` 的工具名；工具名写死在文件顶部的 `GROUPS` 中，用别的扩展时需要照着改。

### rtk：在 Magpie 里打开开关

`rtk` 不用手动 `pi install`，安装和接入都在 Magpie 里完成：先装 RTK 本体，打开开关后 Magpie 自动装好 Pi 扩展。入口是 **Library → magpie → RTK**：

1. 本机还没有 RTK 时，先在该页面点击安装。
2. 在下方 **Agents** 列表打开 **Pi** 开关，Magpie 会调用 RTK 自带的安装器，把扩展写到 `~/.pi/agent/extensions/rtk.ts`。
3. 重启 Pi 生效。

## 二、Magpie：功能很全，日常用好这 4 块就够

Magpie 是一套能力非常完整的工作台中枢，但日常写代码最高频、最顺手的其实是下面四项：

| 高频能力 | 日常怎么用 | 核心收益 |
| :--- | :--- | :--- |
| **多模型路由组** | 按用途分主力执行组、把关组、兜底组 | Pi 对准固定入口，限流与切换无感 |
| **全局 `AGENTS.md`** | 统一托管语言、隐私红线与 Git 提交规范 | 跨项目自动生效，不用每次重复交代 |
| **Artifact 与内置浏览器** | 长方案直出结构化文档，网页直接预览验收 | 告别终端纯文本刷屏，对照更直观 |
| **生图与定时自动化** | 工作流内顺手出配图，定时跑巡检或整理 | 高频周边需求不切工具，一次闭环 |

## 小结

**Pi 管终端里的极速执行，Magpie 管全局调度与周边能力**——两层解耦之后，换模型、增删扩展都不会伤筋动骨。
